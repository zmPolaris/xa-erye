## 三、潜在风险点

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| **XSS 清洗生效**（批次 1） | `/system/*`、`/monitor/*`、`/tool/*` 路径的请求参数中含 script/iframe/javascript: 等关键词的**合法文本会被剔除** | 回归管理端表单（通知公告等富文本）录入与保存 |
| **`ordersInfo` 推送策略变化**（批次 1） | 由"每 6 小时全量重推"变为"变更才推 + 首轮必推" | 观察首轮定时任务是否全量推送一次；后续仅在医嘱变化时推送 |
| **Kafka 异常也 ack**（批次 2） | 处理失败的消息不再重复消费（原行为是重平衡后重投） | 失败已有 error 日志；如需重试需另行引入死信 topic |
| **`OutpdoctConvertService` 去重键统一**（批次 2） | 首次上线时历史遗留的带前缀缓存键失效，当日门诊可能重推一次 | 可接受的幂等重推；下次 5 分钟周期后恢复正常去重 |
| **Druid `maxActive` 20→50**（批次 2） | 数据库连接数上限翻倍，需确认 Oracle/MySQL 承载 | **需 DBA 评估**；如有顾虑可通过 yml 调回 |
| **异常响应文案变化**（批次 3） | 前端若解析/展示 `e.getMessage()` 原文的提示会变化 | 错误码（code）不变，仅 msg 文本统一 |
| **`DateUtils` 解析严格度**（批次 3） | `DateTimeFormatter` 严格度与原 `SimpleDateFormat(lenient=false)` 基本一致；`dateTime(String,String)` 未改动保持宽松解析 | 覆盖日期解析的回归用例 |
| **线程池/同步服务配置启动时加载一次**（批次 3） | 运行期修改 `sys_config` 中服务地址/日志开关需重启生效（原来每次生效） | 文档注明；如确需热更新再评估缓存失效机制 |
